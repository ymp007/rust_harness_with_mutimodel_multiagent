# Production-readiness assessment — 2026-09-30

## Full-screen workspace and model controls — 2026-10-10

Interactive ycode now owns an alternate terminal screen with an anchored bottom composer and a header showing effective manager, developer, reviewer and QA providers/models. Incremental row rendering keeps concurrent output separate from input. The command picker includes editable manager/common-worker/per-role model entries using existing `/model MODEL` and `/models ROLE MODEL [PROVIDER]` controls; changes retain saved session context and routing. Tab off displays/routes inherited manager settings; Tab on restores configured worker settings. Global defaults remain the way to configure fresh sessions across projects.

PageUp/PageDown navigate a bounded 128 KiB/4,000-line live transcript, including Unicode wrapping and preserved history position during incoming output. Resizing reflows the screen (native Windows events, Unix idle polling). Exit/cancellation restores the original terminal screen; noninteractive subcommands and print mode retain plain output. This fills the current terminal viewport rather than maximizing the OS window. The earlier inline-interface assessment below describes the preceding implementation.

Verification: **100 CLI/gateway tests passed** (68 CLI unit, 7 CLI integration, 25 gateway), with strict all-target Clippy. Native Windows pseudo-terminal checks confirmed alternate-screen startup, bottom-anchored input, changing the manager to a separate model from all workers, PageUp navigation and cancellation restoring the original screen. These checks used an isolated local configuration and no model API calls. Unicode/narrow-screen layout bounds, live transcript limits, incoming-output history preservation, role inheritance and non-submitting navigation are covered by regressions. Unix native resize polling has not been interactively verified on this Windows host.

The updated release was installed as `%USERPROFILE%\.cargo\bin\ycode.exe` and its hash matched the release artifact. A final installed-binary check confirmed full-screen startup, distinct manager/worker settings restored by `--resume`, and normal exit restoring the shell screen.

## Prompted design and terminal interface — 2026-10-10

Startup no longer triggers model-driven design generation. With saved design enabled, a successful prompted turn creates/updates `.ycode/design.md` and its canonical cache when source was successfully inspected or files changed. The refresh reuses current-turn tool observations, preserves valid previous architecture and labels proposals/unknowns; greetings and failed source reads do not generate a design. Old raw-source history remains excluded. Explicit `/sudo refresh` remains available. Team implementation with no existing design creates a task-scoped reference only after the implementation request arrives. Refresh errors preserve completed work and the previous usable cache.

The inline terminal interface adds a welcome header, bordered composer, compact mode/provider/model status and a filtered slash-command picker (Ctrl+P, arrows, Enter, Esc). Tab retains immediate multi-model routing. A shared output lock redraws the composer around approvals/worker messages without losing unsent text; Unicode width-aware clipping bounds long prompts. Normal scrollback, terminal restoration and noninteractive stdout/stderr remain available. NO_COLOR disables color; plain terminals disable the invisible picker and fall back to line input where native keys are unavailable. This is an inline terminal interface, not full-screen editor, mouse control or Claude Code/OpenCode feature parity.

Verification: the CLI/gateway regression suite passed (63 CLI unit, 7 CLI integration and 25 gateway tests), followed by the added plain-terminal picker regression. Strict all-target Clippy passed. A native Windows pseudo-terminal smoke check verified startup without a model request/design file, welcome/composer output, `/su` filtering and Tab preserving unsent input while routing changed. Provider credentials and external model calls were not used for these checks. Unix terminal behavior is covered by shared editor tests but was not interactively verified on this host.

The release was installed as `%USERPROFILE%\.cargo\bin\ycode.exe`; its SHA-256 matched the local release artifact. The installed binary's colored welcome/composer and Ctrl+P command palette were also verified in the isolated Windows pseudo-terminal project.

## Native MCP integration — 2026-10-10

The CLI now uses the official Rust MCP SDK (rmcp 3.5.1) through bounded stdio, Streamable HTTP and deprecated HTTP+SSE adapters. Dual-era discovery/initialization, paginated tools/resources/templates/prompts, calls and reads are integrated into single-agent and coordinated-worker requests. Generic MCP bridge tools disclose schemas on demand. Workers start local servers from their own checkouts; `${YCODE_WORKSPACE}` and server-to-client roots identify that checkout. Global/project settings and common `.mcp.json` layouts are supported without importing foreign credential stores.

Separate MCP approvals are required, with an invocation-only `--allow-mcp` option. Server read annotations cannot bypass plan/reviewer/manager restrictions; exact configured read allowlists are enforced. Configurations containing environment values are excluded from source/design/worktree reads. Child processes receive a reduced environment; credentials use environment references. Transport buffers, discovery pages, arguments/output, startup and request durations are bounded. Cancellation tears down active connections and owned process trees; timed-out application actions are not automatically replayed.

Verification: **89 CLI/gateway tests passed** (64 CLI and 25 gateway), plus **11 real-server acceptance checks** against official filesystem/memory/everything servers version 2026.8.31 and TypeScript SDK 1.32.1. Real checks include all three transports, actual tools, resource reads and prompt retrieval. Fixtures verify five protocol versions (2024-11-05 through 2026-07-28), HTTP response variants/session headers, pagination errors, credentials/approvals, deadlines and size limits, no replay after expired HTTP sessions, saved-design agent calls and worker roots. Strict all-target Clippy passed. Cross-platform CI includes the reference checks; the confirmed local result is Windows. No paid model API request was made.

The final optimized executable was installed at `C:\Users\patel\.cargo\bin\ycode.exe`, matched the release artifact's SHA-256, and passed all 11 reference-server checks again through the installed command. Startup deadlines begin after approval; automatic SDK reinitialization/replay after HTTP session expiry is disabled.

Browser OAuth, sampling, elicitation, app UI, user-facing subscriptions and long-running task orchestration remain unintegrated. Binary/media results are returned as bounded JSON rather than rendered multimodal content. Deprecated SSE lacks automatic reconnect. This is broad standards-based interoperability, not a claim that every server or every extension works. See `MCP_COMPATIBILITY.md` for the compatibility matrix and reproduction steps.

Context7 follow-up: the installed Windows binary also passed live hosted-server discovery, library lookup and documentation retrieval in plan mode. Context7 4.3.0 negotiated MCP 2026-07-28. All three checks passed with anonymous access; API-key authentication was not live-tested. A reusable configuration example and optional `scripts/verify_context7.mjs` test are included; see `MCP_COMPATIBILITY.md`.

## Global configuration update — 2026-10-10

Every invocation can reuse `%USERPROFILE%\.config\ycode\config.json` (Unix: `~/.config/ycode/config.json`). `ycode config init` creates a no-clobber template without API access, and `ycode config path` reports its location. `--config` and `YCODE_CONFIG` select another global file; `--no-global-config` isolates an invocation from user-wide settings. Providers, manager/worker models, modes and bounded execution limits are configurable. Credential values remain in the environment, with only variable names in the file; approval grants cannot be made persistent through configuration.

New-session CLI flags override project `ycode.config.json` settings, which overlay global defaults. Existing project provider registries remain compatible and override matching aliases. Resumed sessions preserve saved selections rather than silently adopting changed defaults. Configuration is bounded to 64 KiB, rejects unknown fields and invalid limits, and refuses linked config files; explicitly selected missing files fail. Global settings are not copied into model design context.

Verification: **68 CLI/gateway tests passed** (43 CLI and 25 gateway). New coverage checks reuse from separate projects, project/CLI precedence, global bypass, no-clobber initialization without credentials, invalid configuration, and default/session behavior. No live API request is needed for initialization or configuration diagnostics.

## Multi-model/provider update — 2026-10-09

Manager planning, design and coordination remain on the selected manager model. Developer, reviewer and QA model/API profiles persist independently. Native Tab switches new-worker routing immediately and retains unsent input; active workers retain their original client. A separate atomic mode journal records toggles even while generation is in progress. The line-input fallback exposes `/multimodel`. Session resume retains provider names and worker configuration; task records retain the dispatched model/provider. The full parallel-team workflow also exercises disabled profiles with retained worker overrides.

`ycode.providers.json` configures full endpoint URLs, API formats and credential environment-variable references. The CLI supports OpenAI-compatible Chat Completions, direct Anthropic Messages and Gemini generateContent. Transport shares pooled connections, rejects URL credentials/query strings and redirects, and bounds provider response bodies. Tool adapters preserve result IDs, schemas, native content blocks and Gemini reasoning signatures. Missing credentials are resolved only for selected/dispatched providers; profile off does not require unused worker credentials. Inline configuration keys are rejected and configured credentials are redacted from captured tool results. OpenRouter remains the default and the optional daemon still uses its existing OpenRouter configuration.

Verification: **64 CLI/gateway tests passed** (39 CLI and 25 gateway), with strict all-target Clippy passing. Tests include all three provider tool roundtrips, provider-specific authentication headers, Gemini signatures/idless calls, rejection of truncated/blocked native responses, custom-provider startup without an OpenRouter key, role routing, resume persistence and credential isolation. A real Windows console session verified Tab without Enter, preservation of a partially typed command, restoration of configured worker models, and clean exit. This host did not exercise Unix native terminal behavior.

The release command remains `ycode`. Live API credentials, model availability, worker quality and cost are still unverified. Native Anthropic/Gemini adapters currently support completed responses; plain-chat streaming requires an OpenAI-compatible API. Proprietary request/authentication formats beyond these adapters need a compatible gateway or another adapter. Provider configuration loads at startup. See README and `ycode.providers.example.json` for setup.

The original repository was a systems prototype, despite production labels in its research documents. Existing tests passed but the default CLI invoked a simulated reactor with fixed completion text and token counts. It did not perform a coding-agent loop. The web UI fabricated memory/latency figures and even displayed a test-command success notice without running a tool. Provider configuration derived Debug with an unredacted key, body limits were checked after full allocation, streaming ignored provider error payloads and incomplete termination, and CLI status/start reported success without a verified health check.

The supported path now runs as **`ycode`**, directly connecting a repository tool loop to OpenRouter. Its CLI supports interactive and one-shot requests, read-only reviews, project selection, model selection, saved sessions/resume, and configuration diagnostics. File edits and shell execution require approval unless explicitly authorized for that invocation. There is no daemon dependency or simulated-success fallback in this path.

The optimized `ycode.exe` was installed in the user's Cargo bin directory and its command resolution was verified. Missing-key diagnostics return exit code 1 as intended. Both PowerShell setup/smoke scripts parse successfully. The CLI tests also cover LF edit arguments against CRLF files without changing the surrounding newline style.

No OpenRouter key was supplied during this work. Live model compatibility, account credits, real tool-calling quality, and live streaming remain an acceptance test for the user's account. Offline tests validate the protocol and local behavior, not a provider's availability. Current local verification is Windows; cross-platform CI must run before claiming those platforms are verified.

The CLI is ready for controlled local testing and daily-use evaluation. Full Claude Code parity and broad production certification are outside the implemented baseline. Remaining limitations are documented rather than concealed: agent output is per-response rather than token-streamed; context has a hard 256 KiB bound with `/clear`; MCP/local inference/Wasm/mesh scaffolds and legacy daemon IPC are experimental; no integrated IDE, automatic compaction, signed installers/updater, cost accounting, or general OS filesystem/network sandbox is included. File-path checks target a trusted local workspace and do not provide OS-enforced protection against a hostile process racing filesystem changes.

Research reports and benchmark labels are historical design material. Resource budgets and latency claims require fresh measurements on the target machine; this change does not claim those SLAs are achieved. Existing database files and unrelated local changes were retained.

User branch/index state is preserved using temporary Git indexes; out-of-scope changes and conflicting integrations are rejected. The manager, not comments or model assertions alone, must assess review/test adequacy. See README for limits and controls.
